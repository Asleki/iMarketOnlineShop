# onStore marketplace testing specification

Approved scope: retain the approved header appearance, homepage hero, merchant branding, currency conversion and themes. Replace the homepage shops grid with three offer carousels and the visitor's first five selected departments. First-time homepage visitors choose at least five unique categories; preferences persist locally and synchronize to signed-in profiles. Categories can be edited later.

All cards, search results and featured links resolve to `product.html?id=<canonical-id>`. The shared detail page provides galleries, descriptions, actual review counts (three reviews displayed), stock, cart and related products. Shops move to `shops.html`; each `shop.html?shop=<slug>` has its own hero, navigation, categories, offers and trending products. Header/footer implementations are shared on every page. Profile, cart, search, collection, contact and attribution pages complete navigation.

Testing backend: Node.js >=22.13 with built-in SQLite, under `backend/`. Serve the frontend and JSON API together. Persist customer accounts (scrypt password hashes), revocable HttpOnly sessions, addresses, preferences, cart, reviews, product publication dates/views, stock and shop-owned offers. Never commit databases, passwords, session tokens or credentials. SQLite seed data is the existing testing inventory, not verified live merchant stock. Property designs remain references without fabricated sellable quantities. Preserve source catalogue/media/brand bytes.

Customer level starts at Starter/0. Testing policy: one point per active browsing minute (at most 30/day), five per unique review, one per completed USD spent. Tier thresholds: Bronze 100, Silver 500, Gold 1500, Diamond 5000. No spending points are issued until a future payment/order system records verified completed purchases. Server calculates all progress; clients cannot write levels or spending. Browser heartbeats stop while hidden/idle, server caps elapsed credit and shares activity timestamps across tabs.

Offer timers use server UTC deadlines and expire without resetting on refresh. Publication timestamps are written once on first backend import; arrivals qualify for 30 days. Existing flash sales may already be expired: never invent a live deadline. Shop admins can be provisioned locally through an environment-secret CLI and manage only their own stock/offers in a minimal authenticated offer page. Public merchant signup, billing, custom admin domain, checkout, payment methods and GCP deployment are deferred. No public role promotion.

GitHub Pages remains a static browsing fallback; customer account services require `npm start` or a separately deployed backend. It must report unavailable services honestly, never store passwords locally or pretend to authenticate. Guest preferences/cart can work locally. Runtime configuration stays portable for a later private onStore/GCP repository.

Validation: existing applicable asset/hero/currency/commerce checks, new API integration tests (isolation, auth, stock bounds, offers, persistence, expiry, reviews and preferences), and desktop/mobile browser journeys. Update obsolete modal/home-grid tests to reflect explicitly approved behavior. Publish a normal commit after checks; no force push.
